# Repository instructions

Read `ARCHITECTURE.md` for platform contracts and `CONTRIBUTING.md` for contribution conventions.

## Product and documentation direction

Position k-shui as **open-source, agent-driven Kafka management**. Lead product
documentation with **k-shui Agent** investigations, evidence, and reviewed
operations. Use **k-shui engine** as the product name for the backend, and present
the visual workspace as the companion for resource inspection and expert control.

Keep implementation names, API paths, provider identifiers, and configuration
values accurate in technical references. Distinguish current agent capabilities
from the broader workspace and future work. Document explicit agent enablement,
authentication, scoped tools, human-reviewed changes, and current deployment
limits. Never imply unattended remediation or unsupported agent operations.

Preserve historical release records and legal text; product positioning does not
rewrite release history or change the application contract.

## Publish finalized plans

Every finalized plan for this repository must be published as a new GitHub Project owned by `thadchas` and linked to `thadchas/k-shui`, with a matching repository milestone, one repository epic containing the complete plan, and actionable repository issues covering its deliverables.

- Include scope, dependencies, and acceptance criteria in the issues. Link child issues to the epic, add them to the project and milestone, and start new work in Todo.
- Reuse and reference existing issues when work overlaps. Do not move an existing issue out of another milestone merely to reference it.
- Revisions update the same project, milestone, and issues. Check for existing items before publishing so retries do not create duplicates.
- Default projects to private, matching the existing repository project convention. Issues follow repository visibility. Do not include secrets or private account information.
- Put the epic URL and deliverable in the project README. Do not invent deadlines or mark planned work complete.
- Return the project, milestone, and issue URLs after verifying repository linkage and membership.
- When plan mode, permissions, or access restrictions prevent publication, explicitly report publication as pending; do not claim that GitHub items exist.

Apply this policy to future finalized plans and the AWS demo architecture and pricing plan. Do not retroactively publish unrelated historical plans unless requested.
